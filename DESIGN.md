# DiffTrial design direction

Software workbench for developers inspecting code repairs. Energy 1 / Rhythm 2 / Motion 1, supplied in the project brief.

- Warm paper (`#f5f3ee`) and dark charcoal (`#1b211f`) support extended reading without a glossy marketing treatment.
- Teal (`#176358` / `#93d7be`) identifies selection and positive execution evidence; textual labels keep meaning independent of color. A restrained error color is reserved for failures and removed lines.
- Segoe UI / system sans keeps controls familiar and readable. Cascadia Code / Consolas is reserved for code, identifiers and hashes.
- A ledger of ruled rows makes tasks comparable. Run details put the actual diff beside baseline and patched evidence; the diff signs repeat the product's identity through real content.
- A compact spacing scale (8, 12, 16, 20, 24, 32, 40, 48 pixels) distinguishes rows, panels and page sections. No decorative feature cards, illustrations, icons or photos are needed.
- The three requested destinations are Runs, Compare, and Benchmarks. Local creation and provider settings are a separate local-only route.
- At narrow widths, four keyboard-operable evidence tabs replace the split panes. Mid-size screens use denser task rows before the full desktop table appears.
- Light and dark modes share the same semantic tokens. Focus rings remain visible in both. Motion is limited to native state feedback and a one-pixel button press; reduced-motion preference is respected.
- No invented run history. Browser fixtures remain exclusively in tests. The published dashboard loads only selected measured runs, or an honest empty state.

The brief describes an application, so landing-page skill defaults such as full-screen marketing heroes, stock photographs, shader scenes, and randomized palettes do not apply. They would conflict with the explicitly requested workbench, text-only branding, fixed palette, and motion dial.
